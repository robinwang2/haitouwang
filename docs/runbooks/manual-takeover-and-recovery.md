# 人工接管与恢复手册

## 触发条件

验证码、测评、视频面试、电子签名、未知必填项、法律/身份问题、工作授权歧义、页面结构变化、凭证需求、策略阻断或提交结果不确定时，自动化必须停止。禁止猜答、绕过、静默重试或重复点击提交。

## 接管步骤

1. 确认申请处于 `manual_required` 或 `submitted_pending_verification`，记录非敏感 request/correlation/application ID。
2. 核对人工任务包只包含目标 URL、材料/事实引用、风险码、未决问题和恢复动作；发现正文、Cookie、验证码或令牌立即按 SEV-1 处理。
3. 用户在本地浏览器完成验证码、身份/法律回答或结果核验。云端支持人员不得索取或代填凭证、Cookie、验证码。
4. 提交结果不确定时，先查询第三方状态或确认邮件/编号；不得重新提交。只有可验证第三方证据才能标记 `submitted`。
5. 风险解除后，用户显式恢复到契约允许的 `filling` 或 `awaiting_confirmation`；恢复不会自动提交，仍须新的有效确认。

## 恢复验证

- 原人工原因保留在时间线和审计中。
- 恢复使用新命令和新的确认授权；旧确认不得重放。
- 相同代理 command/sequence 的重复回执返回原结果，不产生第二次副作用。
- 看板只有一条申请，日报来源记录可回查，人工任务历史可见。
- 无可信证据时状态仍为 `submitted_pending_verification`。

## 进程或数据恢复

当前业务服务为内存实现，进程重启会丢失状态，不能执行生产数据恢复。候选环境只能重新创建测试数据并重跑门禁。生产恢复必须等持久化、备份和 RPO/RTO 决策完成后演练；在此之前 `REL-002`、`REL-003` 不得解除。

未来恢复演练必须：隔离恢复到新环境、校验租户计数和审计链、确认幂等/回执唯一约束、验证对象与索引引用、通过跨租户和主路径烟测，最后由授权人员决定切换。
