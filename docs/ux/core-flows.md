# 海投王 MVP 核心流程与交互规格

- 工单：海投王-0-4（`ux_spec`）
- 版本：1.0
- 日期：2026-07-30
- 状态：可供交互实现；接口字段和合法状态迁移仍以未来 `domain_contracts` 为准
- 依据：`docs/decisions/product-baseline.md`、`施工计划.md`、《海投王_智能求职平台完整产品策划案_更新版》

## 1. 目标与边界

本文定义 MVP 从“发现职位”到“用户确认提交并留下申请记录”的客户端体验，覆盖：

1. 首页控制台；
2. 职位池；
3. 审核中心；
4. 申请看板；
5. 平台与本地代理连接；
6. 本地辅助填写、提交前确认和人工接管。

MVP 自动化等级固定为等级 1：系统可以生成材料并辅助填写，但必须在提交前停止，由用户明确确认。验证码、在线测评、视频录制、电子签名、未知法律或身份问题、工作授权歧义、页面结构变化、文件上传失败，以及无法确认提交结果时，必须暂停并转人工。界面不得提供绕过这些门禁的入口。

资料中心、规则中心、面试和分析页面不在本文范围。界面默认语言和首发地区尚未由产品负责人确认，因此本文描述文案意图，不锁定最终 locale、日期格式、货币或法域相关措辞。实现时所有用户可见文案必须使用本地化资源，不能把本文中文直接硬编码为唯一文案。

## 2. 契约使用约定

本文中的字段名是界面语义，不是 API 字段名。前端实现必须使用 OpenAPI 生成或校验的类型，并将语义字段映射到 `domain_contracts` 的最终字段；不得根据本文另建并行状态机。

- 所有资源均按当前用户隔离；服务端返回无权限时，客户端不得通过缓存、URL、通知或错误详情泄露资源内容。
- 任何“提交成功”状态都必须有可验证证据。只有用户自述、浏览器超时或未知回执时，保持“待确认”，不得显示为成功。
- 未知枚举值使用“状态暂不可识别”中性样式，并提供刷新或查看详情，不得映射为成功。
- 所有会改变开关、审批结论、申请状态或连接授权的操作都需要审计；成功反馈包含时间和结果，不显示令牌、Cookie、验证码或原始凭证。
- 写操作失败时保留用户尚未提交的编辑内容；重试必须依赖契约提供的幂等能力，不能通过前端重复创建记录。

## 3. 全局信息架构与页面骨架

主导航顺序固定为：首页、职位池、审核中心、申请看板、连接。当前项同时用视觉样式和 `aria-current="page"` 标识。

页面共享以下区域：

- 顶部：当前求职目标切换、通知入口、用户菜单。
- 全局状态带：仅在全部或部分自动化暂停、代理离线、权限变化时出现；说明影响范围、原因、发生时间和唯一推荐动作。
- 页面标题区：标题、简短说明、主要操作。每页最多一个视觉主操作。
- 内容区：列表、详情或看板；加载时保持主要布局稳定。
- 反馈区：页面级错误放在标题下方；字段错误紧邻字段；短暂成功消息用状态区域播报。

直接访问深层链接时，先校验会话和资源权限，再渲染资源。未登录跳转登录并保留安全的返回路径；无权限显示不含资源名称和内容的权限页。

### 3.1 全局状态规则

#### Loading

- 首次加载显示与最终布局近似的骨架，不使用空数据插图代替加载状态。
- 局部刷新保留旧内容，刷新区域标记 `aria-busy="true"`；不得清空筛选、滚动位置或未保存编辑。
- 按钮发起写操作后显示进行中并阻止同一操作重复触发，但“取消”或“返回安全状态”仍可用。
- 加载超过预期时显示“仍在处理”的非破坏性提示；不可谎报成功。

#### Empty

- 区分“账户尚无数据”和“当前筛选无结果”。前者给出首个可执行动作，后者提供“清除筛选”。
- 空状态不显示 0 值成功率或误导性趋势。
- 因暂停或权限导致不可见时，不得伪装成空数据。

#### Error

- 页面级失败包含：发生了什么、哪些内容可能未更新、用户可做的恢复动作、可供支持定位的非敏感请求编号。
- 列表局部失败不遮挡其他已成功区域；提供“重试此区域”。
- 写入结果未知时使用“结果待确认”，禁用重复提交，并先查询最终状态。
- 输入校验错误聚焦到错误摘要，摘要链接回对应字段；不要只用 toast。

#### Permission

- 页面无查看权限：显示权限说明和返回入口，不渲染资源骨架或缓存内容。
- 有查看但无编辑权限：保留信息可读性，操作显示为不可用并说明所需能力；不可只隐藏高风险操作而不解释。
- 操作期间权限被撤销：停止后续写入、保留本地草稿、显示重新验证或联系管理员的动作。
- 权限语义按 `canView`、`canEdit`、`canApprove`、`canOperateAgent` 等能力表达，具体角色名称由后续契约决定。

#### Paused

- “暂停”是明确业务状态，不等同于错误或离线。状态带必须显示暂停范围、触发原因、触发时间、受影响任务数和恢复条件。
- 用户仍可浏览历史记录、审核材料、下载手动任务包和撤销连接；会启动新自动化任务的操作不可用。
- 系统暂停只能在恢复条件满足后继续；不能用通用“忽略并继续”绕过。
- 用户主动全局暂停后，恢复需要明确确认；确认文案列出将重新启动的能力，且不得开启 MVP 的自动提交。

## 4. 首页控制台

### 4.1 目的与结构

首页回答三个问题：“现在是否安全运行”“我今天先处理什么”“最近发生了什么”。从上到下展示：

1. 自动化与连接状态：全局暂停状态、本地代理在线状态、最近心跳、受影响任务，以及进入连接页的动作；
2. 今日待办：待审核、待用户确认提交、需人工接管、结果待确认；按截止风险和阻塞优先排序；
3. 职位摘要：今日新职位、高匹配职位、被硬规则拦截或高风险职位；
4. 申请摘要：今日已确认投递、待确认、失败或暂停；
5. 最近活动：职位发现、审核决定、代理暂停和申请证据的时间线。

统计卡必须同时显示标签、数值和统计时间范围。数值是可导航入口；例如“待审核”进入保留对应筛选的审核中心。

### 4.2 主要操作

- “查看下一项待办”：进入排序后的第一项；若没有待办则不显示。
- “导入职位链接”：进入职位池导入流程。
- “处理代理问题”：仅在代理离线或暂停时出现，进入连接或对应接管任务。
- “暂停全部辅助操作”：始终可达，打开确认对话框并说明进行中的任务如何安全停止。

暂停是高优先级安全操作，不要求复杂二次确认；恢复则必须确认范围。暂停请求结果未知时保持“正在确认暂停”，并阻止启动新任务。

### 4.3 页面状态

- Loading：各摘要独立骨架；全局状态优先加载，不因次要统计阻塞安全状态显示。
- Empty：新账户显示“导入第一个职位”；有职位但无待办时显示“目前无需处理”并提供职位池入口。
- Error：全局状态加载失败时按未知状态处理，禁止启动辅助填写；单个摘要失败不影响其他摘要。
- Permission：无对应能力的摘要仅展示允许的聚合信息；不可通过链接进入受限记录。
- Paused：页首常驻暂停带，待办优先展示恢复条件和人工任务；不得把暂停任务计入“失败”。

## 5. 职位池

### 5.1 列表与筛选

桌面宽屏采用“列表 + 详情”双栏；窄屏先显示列表，详情作为独立层级并保留返回后的筛选和滚动位置。默认按推荐优先级和发布时间排序。

每条职位至少展示：

- 职位名称、公司、地点/远程方式、来源及原始链接；
- 发布时间、截止时间（如有）、匹配分数及分段说明；
- 工作授权结论、风险等级、硬规则结果、重复/合并提示；
- 当前处理状态、推荐申请方式、预计耗时；
- 收藏状态和需要用户处理的未决项数量。

筛选包含：关键词、求职目标、匹配分段、发布时间、地点/远程、公司、来源、工作授权结论、风险等级、当前状态。已启用筛选以可移除标签展示，并支持“一键清除”。结果数变化通过礼貌型状态区域播报，不在每次键入时抢夺焦点。

### 5.2 职位详情

详情按顺序展示：职位摘要、硬规则与风险、匹配优势、潜在不足、申请策略、完整职位描述、来源与合并记录。分数旁必须同时展示文本结论；硬规则拦截优先于高分，不能因分数高而弱化。

主要操作按状态出现：

- “加入审核/生成材料”：仅对未被硬规则拦截且用户有编辑能力的职位可用；
- “收藏”与“忽略”：变更后可撤销，并写审计；
- “打开原始职位”：明确将离开产品，使用安全的新窗口行为；
- “报告风险判断有误”：收集反馈，但不会立即解除硬门禁；
- “导入职位链接”：校验 URL，仅接受 MVP 支持来源或明确标记为手动来源。

高风险、过期、授权不符或重复职位不提供自动化继续入口；若产品允许人工查看，则提供“创建人工核查任务”，且持续显示风险原因。

### 5.3 页面状态

- Loading：筛选条可用后优先显示；列表与详情各自骨架；分页加载不替换已有结果。
- Empty：无职位时引导手动导入；筛选无结果时保留筛选并提供清除；全部被门禁拦截时说明数量并提供查看拦截项。
- Error：导入解析失败保留 URL 并给出支持来源；列表局部失败可重试；详情失效时返回列表且不清除筛选。
- Permission：只读用户可查看允许字段但不能收藏、忽略或发起生成；无查看权限不泄露职位详情。
- Paused：仍可搜索、筛选和查看；若暂停范围包含搜索则显示数据最后更新时间，若包含生成/填写则相应操作不可用并链接到原因。

## 6. 审核中心

### 6.1 队列

队列按“必须修复 → 等待用户回答 → 可批准”排序。每项展示职位/公司、材料版本、评审完成时间、必须修复数、待确认事实数、各独立评审状态和整体建议。整体建议不能只显示单一总分。

筛选包含：求职目标、阻塞类型、评审状态、材料类型、截止时间。进入审核项后，用户可在上一项/下一项间移动；若有未保存编辑，离开前提示保存、放弃或留在当前页。

### 6.2 审核工作区

工作区包含：

1. 职位与硬条件摘要；
2. 定制简历、Cover Letter、开放题标签页；
3. 相对基础版本的逐项差异，新增、删除和修改不能只靠颜色区分；
4. 每项陈述的事实来源、事实版本、允许范围和确认状态；
5. ATS、硬条件、匹配、招聘官、Hiring Manager、事实一致性和自然度等独立评审结果及证据；
6. 必须修复项、建议项和用户待回答问题；
7. 完整版本历史与审核活动。

选择正文中的陈述时，同步定位事实证据；选择证据时反向高亮所有引用位置。无来源或来源不允许的陈述必须标为阻塞，不能批准。

### 6.3 编辑、批准与拒绝

- 编辑：保存草稿与版本；自动保存失败时保留本地内容并明确标记“尚未同步”。
- 标记已解决：必须关联修订或用户说明；不能仅隐藏问题。
- 批准：仅在所有必须修复项关闭、必需回答完成、事实复核通过且评审结果已完成时可用。确认对话框列出职位、材料版本、尚存建议和批准后动作；确认后生成审计事件。
- 拒绝：要求选择原因，可选补充说明；拒绝不会删除职位或历史版本。
- 重新评审：产生新评审运行并保留旧结果；运行期间旧版本可读但不可批准为最新版本。

批准只表示“允许进入辅助填写”，不等于授权提交。按钮和成功文案不得使用“已申请”或“已投递”。

### 6.4 页面状态

- Loading：长材料分段加载并显示标签页级进度；评审运行中展示阶段，不伪造百分比。
- Empty：无待审核项时提供职位池入口；当前筛选为空时可清除筛选。
- Error：某个评审器失败时保留其他独立结果，整体标记“评审不完整”并禁止批准；材料保存失败保留草稿。
- Permission：无批准能力者可查看和评论允许内容；批准/拒绝操作不可用并说明原因。无事实查看能力时不得显示被遮盖内容的长度或片段。
- Paused：AI 生成或评审暂停时可继续查看/编辑已有材料，但不能批准不完整结果；全局辅助填写暂停不阻止完成审核。

## 7. 申请看板

### 7.1 视图与展示分组

看板展示由领域状态派生的用户可理解分组，不自建状态迁移。MVP 至少提供：待处理、审核中、准备申请、申请中/待确认、已确认投递、后续进展、结束。具体领域状态（如新发现、待生成材料、待审核、准备申请、已投递、收到确认、被拒绝、用户放弃、职位关闭）由契约映射到这些展示分组。

每张卡片展示：职位、公司、当前状态、状态更新时间、截止时间/逾期、下一动作、材料版本、风险/暂停标记、申请方式和证据状态。不得只用列位置表达状态，卡片本身必须含状态文本。

支持按求职目标、公司、状态、更新时间、截止时间、申请方式、证据状态和人工任务筛选；同时提供等价的列表视图。拖拽不是唯一操作方式，卡片菜单提供键盘可用的“移动到”动作，且只显示契约允许的迁移。

### 7.2 申请详情

详情包含：职位快照与原始链接、批准材料及版本、申请步骤、手动任务包、截图/确认编号等证据、状态时间线、失败与重试记录、审计活动。

- 用户发起合法状态变更前，界面说明影响并收集契约要求的信息。
- “已确认投递”必须绑定可信回执、确认编号或可验证证据；证据不足时只能进入“待确认”。
- 重复回执显示为同一时间线事件的更新，不新增重复申请卡。
- “用户放弃”需要确认并说明可恢复性；不得删除历史。

### 7.3 页面状态

- Loading：各列保持宽度的骨架；切换列表/看板不重复丢失筛选。
- Empty：无申请记录时引导到职位池；单列为空时使用简短占位，不扩大成整页插图；筛选为空可清除。
- Error：单列失败独立重试；状态变更结果未知时锁定该卡的重复迁移并查询最终状态。
- Permission：无编辑能力时进入只读看板；不允许的迁移不会出现在菜单中，但状态详情说明权限限制。
- Paused：暂停卡保留在其业务阶段并附加“已暂停”标记，不自动移动到失败列；可直接打开暂停原因或人工任务。

## 8. 连接

### 8.1 连接总览

连接页分为“本地代理”和“职位来源”。每个连接卡展示：名称、状态文本、能力范围、最近成功时间/心跳、会话或授权到期时间、暂停原因、受影响任务数和主要恢复动作。

连接状态至少可表达：未连接、配对中、在线、离线、授权即将到期、已过期、已撤销、暂停、错误、未知。未知状态使用中性样式且不能显示绿色成功标记。

职位来源仅覆盖 MVP 支持的 Greenhouse、Lever、公司 Careers 结构化页面和手动 URL。任何来源不可用时，已有职位记录仍可查看，页面说明新数据可能未更新。

### 8.2 本地代理配对

配对流程：

1. 用户选择“连接本地代理”，阅读本地/云端职责和凭证边界；
2. 云端创建一次性、短时有效的配对码或安全链接，并显示到期时间；
3. 用户在本地代理确认账户和请求能力；
4. Web 等待心跳并显示可取消的进度；
5. 成功后展示设备可识别名称、配对时间、最近心跳和已授权能力，不展示令牌；
6. 超时、码已使用或被拒绝时回到可安全重试状态，旧码立即失效。

撤销配对需要确认受影响的进行中任务；撤销后不再领取新任务，已有浏览器会话按安全协议终止，Web 等待服务端确认后再显示“已撤销”。

### 8.3 自动化能力

连接页展示搜索、材料生成、辅助填写和提交四项能力状态。MVP 中“提交”固定关闭并标注“每次提交都需用户确认”，不能在此页开启自动提交。搜索、生成和填写开关的每次变更都需要明确确认，确认中列出影响范围；变更成功写入审计。

若开关状态读取失败，按关闭/未知处理，不能乐观显示为开启。恢复暂停不会改变用户原有开关，也不会开启提交能力。

### 8.4 页面状态

- Loading：先展示本地代理安全状态，再加载次要元数据；操作在真实状态确认前不可用。
- Empty：无代理时提供安装/启动和配对步骤；无职位来源时说明手动 URL 仍可用。
- Error：配对码创建失败可重试；心跳中断显示最后在线时间；撤销结果未知时禁止新任务并查询最终状态。
- Permission：无连接管理能力者只能查看脱敏状态；不展示配对码、撤销或开关操作。
- Paused：明确是全局、能力、连接还是单任务暂停；提供满足条件后的恢复动作或人工接管入口。

## 9. 本地辅助填写、提交确认与人工接管

### 9.1 正常辅助填写

入口来自已批准审核项或“准备申请”的看板卡。启动前预检并展示：职位/公司、申请入口域名、批准材料版本、已知问题、代理状态和将执行的能力。预检失败不打开自动化任务。

进度步骤为：打开页面、识别表单、填写已确认字段、上传批准材料、完整性检查、等待用户确认、确认结果。当前步骤、已完成步骤和暂停原因必须用文本表达。用户可随时“安全停止”；停止后不自动回滚招聘网站已填内容，但会说明浏览器中的残留状态。

到达提交前：

- 本地代理停止所有自动动作并把浏览器交给用户；
- Web 和本地端同时显示“等待用户确认”，列出公司、职位、入口域名、材料版本和仍需复核的回答；
- 默认焦点落在“返回检查”，而不是提交动作；按 Enter 不得直接提交；
- 提交动作使用明确文案“确认提交一次”，不能与“保存”“继续”混淆；
- 一次确认只授权当前职位、当前材料版本、当前浏览器会话的一次尝试；超时或页面变化后必须重新确认；
- 点击后显示不可重复触发的进行中状态，直到取得确定回执或转为“结果待确认”。

### 9.2 强制人工接管触发

以下任一条件触发后立即暂停当前任务，不静默重试、不跳过字段、不自动提交：

- 验证码、登录过期、在线测评、视频录制、人工签字或电子签名；
- 未知必填题、法律/身份问题、工作授权歧义；
- 页面结构变化，导致字段或提交动作无法可靠识别；
- 文件上传失败、平台警告、连续失败或网络异常；
- 提交结果无法确认。

暂停界面展示：触发类型、发生步骤、已经完成的动作、尚未完成的动作、是否可能已经提交、用户需完成的具体步骤，以及“不要重复提交”等风险提示。界面不得显示或上传验证码、Cookie、密码等敏感内容。

### 9.3 人工接管流程

1. 系统暂停并保存脱敏进度，申请记录标记为“已暂停”或“结果待确认”，而不是失败/成功；
2. 用户打开人工任务包，查看职位链接、批准材料、建议答案、风险、未决问题、截止时间和预计耗时；
3. 用户在本地浏览器完成需要本人处理的步骤；Web 不尝试读取验证码、密码、签名或敏感回答；
4. 用户选择“已完成”“仍被阻塞”或“放弃”；
5. 选择“已完成”后收集允许的确认编号、回执或截图元数据并校验；证据不足时进入“待确认”；
6. 若仅完成阻塞步骤且尚未提交，用户可选择“交还给代理继续检查”。系统重新识别页面和预检，不能从旧步骤盲目续跑；
7. 最终结果写入同一申请时间线，重复回执不得创建第二条申请。

“仍被阻塞”允许更新原因和下一步，不重置截止时间或丢失已完成步骤。“放弃”需要确认，保留任务包和历史记录。

### 9.4 接管状态

- Loading：任务包分段加载；安全提示和“停止任务”优先可用。
- Empty：不存在接管任务时回到申请看板；任务已被其他会话解决时显示最终状态和时间。
- Error：任务包部分失败时禁止继续自动化，但允许打开原始链接和下载已成功加载的材料；上报完成失败时保留用户输入。
- Permission：无代理操作能力时不得领取或恢复任务；可按查看权限查看脱敏历史。
- Paused：显示暂停作用域和恢复条件；系统门禁未解除时不显示绕过式“继续”。

## 10. MVP 用户旅程

### J1：从新职位到审核队列

1. 用户在首页打开“高匹配职位”，进入带筛选的职位池；
2. 查看硬规则、风险和匹配解释；
3. 对允许的职位选择“加入审核/生成材料”；
4. 任务创建成功后进入审核中心或返回职位池继续浏览。

异常分支：职位过期/高风险/授权不符时只能查看解释或创建人工核查；生成暂停时保留职位并显示恢复条件；创建结果未知时先查状态，不能重复创建。

### J2：审核并批准材料

1. 用户从首页待办或审核队列进入审核项；
2. 检查材料差异、事实来源、独立评审证据和必须修复项；
3. 编辑或回答问题，等待重新评审；
4. 所有门禁通过后确认批准当前版本；
5. 项目进入“准备申请”，但尚未投递。

异常分支：评审不完整、事实无来源、保存失败或权限不足时不能批准；AI 暂停时可编辑已有内容但不能把不完整结果标为已批准。

### J3：辅助填写并由用户确认提交

1. 用户从申请看板启动已批准申请；
2. 系统完成预检，本地代理打开页面、填写和上传；
3. 代理在提交前停止并把浏览器交给用户复核；
4. 用户明确授权当前会话提交一次；
5. 有可信证据时记录为已确认投递，否则记录为待确认。

异常分支：连接离线、权限被撤销或全局暂停时不得启动；写入结果未知时禁止重复提交。

### J4：异常后人工接管

1. 代理命中强制降级条件并立即暂停；
2. 用户从首页、连接页或看板打开同一个人工任务；
3. 根据任务包在本地浏览器处理未知问题；
4. 用户报告已完成、仍阻塞或放弃；
5. 系统校验证据并更新原申请，不创建重复记录。

异常分支：提交状态不确定时始终进入待确认；门禁未解除时不允许交还代理盲目继续。

### J5：配对、掉线与恢复

1. 用户在连接页创建一次性配对请求并在本地代理确认；
2. Web 收到心跳后显示在线和授权范围；
3. 掉线或授权过期时，受影响任务暂停并在首页提示；
4. 用户重新启动、重新配对或撤销；
5. 状态确认恢复后，用户明确选择是否恢复原任务。

异常分支：过期、已使用或被撤销的配对码不可重用；恢复连接不自动提交、不自动恢复被安全门禁暂停的任务。

## 12. 响应式要求

- 大屏：职位池、审核中心使用双栏；申请看板允许横向分组，但页面本身提供明确横向滚动提示和列表替代视图。
- 中屏：详情区可收起，队列和内容分步展示；主要操作保持在可见标题区或粘性操作栏。
- 小屏：单列层级；筛选放入可关闭的全屏面板，打开按钮显示已启用数量；表格改为带字段标签的卡片，不通过缩小字体硬塞。
- 任何宽度下都不能隐藏暂停原因、风险、状态文本、提交确认或人工接管动作。横竖屏切换后保留草稿、筛选和当前审核位置。
- 点击/触控目标至少 44 × 44 CSS 像素；内容放大到 200% 时不丢失功能，400% 重排时无二维滚动（申请看板可使用有明确替代的受控横向区域）。

## 13. 无障碍要求

目标为 WCAG 2.2 AA，并至少满足：

- 使用语义化标题、导航、主内容、表单、列表和对话框；标题层级连续，每页一个明确的一级标题。
- 所有功能可仅用键盘完成。打开对话框后焦点进入，关闭后回到触发元素；不得形成焦点陷阱。
- 跳转后焦点移到页面标题；列表到详情后移到详情标题；校验失败先聚焦错误摘要。
- Loading 使用 `aria-busy`；短成功消息用 `role="status"`；阻止继续的错误用 `role="alert"`，避免重复播报。
- 状态、风险、差异和评审结论使用“图标 + 文本 + 颜色”，不得仅靠颜色、列位置或动画表达。
- 表单字段具有持久可见标签、帮助文本和关联错误；必填状态同时用文本表达。
- 图标按钮有可访问名称；截图若承载申请证据则提供替代说明，装饰图像从辅助技术隐藏。
- 支持减少动态效果；骨架不闪烁；倒计时同时显示绝对到期时间且不会每秒打断读屏。
- 对话框的危险或高风险动作使用完整动词短语。提交确认默认焦点不得落在“确认提交一次”。
- 拖拽、悬停和手势均提供等价的点击/键盘操作；看板提供列表视图。
- 文本与背景对比度至少 4.5:1，大字号至少 3:1；非文本控件和焦点指示至少 3:1；焦点样式清晰且不被粘性区域遮挡。
