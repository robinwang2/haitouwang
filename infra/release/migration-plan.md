# MVP 数据迁移计划

## 当前状态

仓库没有业务表迁移或持久化 Repository；Applications、Reporting 等当前实现使用进程内存。`infra/dev/postgres-init/001-vector.sql` 只启用开发环境的 pgvector，不是业务数据迁移。当前候选不存在可宣称完成的生产数据迁移，也不存在重启后恢复业务状态的能力；这是 `REL-002` 发布阻断项。

## 首个持久化版本必须满足

1. 建立带租户键、版本、唯一提交幂等键、回执唯一键和追加式审计/outbox 的业务表；外键和唯一约束必须在数据库层生效。
2. 迁移必须可重复检测、事务化或有明确断点恢复方式；向前迁移先兼容旧代码，数据回填和约束收紧分阶段执行。
3. 回填按稳定游标分批，记录行数、失败键和校验摘要，不在日志中输出敏感正文。
4. 迁移前备份必须完成恢复抽检；迁移后核对租户计数、状态分布、幂等键唯一性、审计链和 outbox 积压。
5. 降级窗口内禁止删除旧列或旧事件版本；破坏性清理安排到独立、已批准工单。

## 迁移判定

- Go：预发布全量演练通过，校验差异为零，应用版本向前/向后兼容，恢复演练满足已批准 RPO/RTO。
- Stop：租户计数不一致、唯一约束冲突、审计/outbox 丢失、迁移超时或备份无法恢复。
- Rollback：停止写流量，按 `docs/runbooks/rollback.md` 处理；数据库仅执行已评审的逆迁移，默认优先应用回退并保留向前兼容结构。
