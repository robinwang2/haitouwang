# 海投王

## 这是什么

本仓库是"海投王"求职平台的工程仓库。项目按 [`施工计划.md`](./施工计划.md) 推进。当前第一阶段先交付可独立验收的简历生成 MVP：

> 输入 JD 文本 + 读取 JSON RAG 文件 → 分析岗位要求 → 召回相关个人事实 → 生成定制简历 → 校验每项陈述的事实依据 → 展示可复制的新简历与引用。
>
> —— 《施工计划.md》第 1 节

仓库根目录还保留着产品策划案原始文档（`海投王_智能求职平台完整产品策划案_更新版.docx`），是完整产品路线图的制定依据。职位发现、智能评审、辅助投递、申请管理和分析等能力保留在后续阶段，不作为当前简历生成 MVP 的发布阻塞项。

## 当前 MVP 边界：只生成，不投递

当前 MVP 只生成处于 `review_required` 状态的简历草稿，不自动批准、填写或投递。JSON 暂时只是 RAG 数据源适配器，详细格式确认后只替换映射层；检索、生成、事实校验和界面不直接依赖外部 JSON 字段。自动填写和规则内自动投递属于后续路线图。

## 目录结构

| 目录 | 装什么 |
|---|---|
| `apps/` | 面向用户的可运行应用：Web 前端、云端任务驱动的本地代理、独立启动的本地代理程序 |
| `contracts/` | 跨模块接口契约：OpenAPI 定义、事件 JSON Schema、领域 Schema 及成功/拒绝/降级样例 |
| `docs/` | 架构、产品决策、QA 验收报告、运行手册、安全威胁模型、UX 流程规格，以及按主题整理的 wiki 事实条目 |
| `evals/` | AI 能力（如多代理评审）的评测黄金集与验证报告 |
| `infra/` | 基础设施配置：本地开发依赖编排、发布部署与迁移方案 |
| `services/` | 后端服务，按领域模块（profile、jobs、matching、knowledge、materials、review、agent、applications、reporting）划分 |
| `tests/` | 跨模块端到端验收测试，按里程碑（m1、m2、mvp）分目录 |
| `tooling/` | 工作区级工具脚本：代码检查、格式化、密钥扫描、契约校验、类型检查 |

## 从哪儿读起

1. [`施工计划.md`](./施工计划.md) —— 项目背景、里程碑、任务图、跨模块契约所有权和工单分配规则，是理解本仓库全貌的起点。
2. `docs/decisions/product-baseline.md` —— 产品与技术决策记录（M0 `decision_gate` 产出）。
3. `docs/architecture/` —— 领域模型、状态机、契约约定、云端/本地代理配对协议。
4. `docs/security/threat-model.md` —— 隐私与威胁模型。
5. `docs/ux/core-flows.md` —— 核心页面与交互流程规格。
6. `docs/qa/` —— 各里程碑的集成验收报告（m1、m2、mvp）。
7. `docs/runbooks/` —— 发布、回滚与人工接管/恢复运行手册。
8. `docs/wiki/` —— 按主题（产品基线、契约、安全与隐私、领域模型）整理的设计事实词条。
